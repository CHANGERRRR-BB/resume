项目Project

线上货运代理
全流程自动化 End-to-end freight-forwarding automation

个人项目，2026Personal project, 2026

面向货运代理实训系统，把跨机构、强单据依赖的业务流程封装成命令行工具：接管已登录浏览器，按单据元数据组装提交内容，依据操作日志跳过已完成步骤，并支持 dry-run 预览。 A CLI tool for a freight-forwarding training system that turns a document-heavy, multi-institution workflow into repeatable commands: it attaches to a logged-in browser, assembles submissions from document metadata, skips completed steps based on the operation log, and supports dry-run previews.

问题Problem

单据类型多、跨机构顺序严格、重复点击和试错都有成本；单据内容仍需人工填写，自动化必须明确边界。 Many document types, a strict cross-institution sequence, and costly repeated clicks and retries. Documents still need manual entry, so the automation has to respect a clear boundary.

做法Approach

用 Python + Playwright 通过 CDP 接管已登录的 Edge；按单据元数据组装提交内容；用操作日志做幂等；提供 dry-run。Claude Code 与 Playwright MCP 用于开发，运行时是确定性程序。 Python + Playwright attach to a logged-in Edge over CDP; submissions are assembled from document metadata; the operation log provides idempotency; dry-run previews the payload. Claude Code and Playwright MCP were development tools; the runtime is deterministic.

反思Reflection

两个阻塞问题经交叉核对，确认由业务系统自身的源数据矛盾导致；解决方式是定位不一致，而不是反复重试。校园网的内外网双通路让云端部署比本地更合适；真实流程还需要异常处理、权限边界和人工协同。 Two blockers were traced—after cross-checking documents and operation logs—to contradictory source data in the business system itself; the fix was to locate the inconsistency rather than retry blindly. The campus network's intranet and extranet paths made cloud deployment a better fit than local; real workflows also need exception handling, permission boundaries, and human collaboration.
